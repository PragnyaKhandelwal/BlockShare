Distributed storage · Smart contracts · Django

File sharing where the data is spread out, and so is the trust.

BlockShare splits every upload into chunks and replicates them across a cluster of storage nodes. Ownership, sharing and version history are handled by the Django server — or, with one switch, by smart contracts on an Ethereum chain.

How it works

The system keeps a strict split between the data plane (where the bytes are) and the control plane (who owns them and who may read them). Only the control plane changes between modes.

Storage network

Files are cut into fixed-size chunks addressed by their SHA-256 hash and placed with consistent hashing.

  • Custom binary protocol over TCP between server and nodes
  • Replicas are copied node to node in a pipeline
  • Nodes gossip UDP heartbeats to detect failures
  • Lost or corrupted replicas are rebuilt automatically

Coordination on-chain

Three Solidity contracts take over when blockchain mode is on.

  • FileRegistry — owners, versions, Merkle roots
  • FileSharing — read / write grants
  • NodeRegistry — where the data lives
  • Every user signs with their own wallet

Web application

A Django app ties it together for end users and administrators.

  • Upload, share, version and verify files
  • Live view of nodes, transfers and the chain
  • REST API with token auth and OpenAPI docs
  • Admin control panel with the mode switch

Two ways to coordinate the same cluster

Switching modes moves the authority over files from the Django database to the contracts (and back). Existing files are re-anchored on-chain when the switch happens.
